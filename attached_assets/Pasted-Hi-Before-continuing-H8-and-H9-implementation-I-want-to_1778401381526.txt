# Weighted Field Enforcement

Every engine output field must have:

```ts
{
  fieldId: string,
  importance:
    | "critical"
    | "important"
    | "supporting"
    | "optional",

  weight: number,

  missingBehavior:
    | "RETRY_THEN_BLOCK"
    | "BLOCK"
    | "CONFIDENCE_DOWNGRADE"
    | "WARN_ONLY"
}
```

Not all fields should be treated equally.

---

# Weighted Signal Enforcement

Every mapped signal must also carry weighting.

```ts
{
  signalId: string,
  sourceEngine: string,
  sourceFields: string[],

  importance:
    | "critical"
    | "important"
    | "supporting"
    | "optional",

  weight: number,

  signalConfidence?: number,
  labelConfidence?: number,

  missingBehavior:
    | "BLOCK"
    | "CONFIDENCE_DOWNGRADE"
    | "WARN_ONLY"
}
```

The system should understand:

* which signals matter most
* which fields support which signals
* which evidence is weak
* which evidence is stale
* which evidence is direct vs inferred

# Retry Logic (Very Important)

We already have retry and repair systems.

Extend them intelligently.

If a CRITICAL field is missing or invalid:

1. detect exact missing field
2. retry ONLY the affected engine
3. re-retrieve / regenerate the missing field
4. recompute the affected signals
5. retry downstream reasoning if needed
6. if still invalid → CONTRACT_INCOMPLETE + BLOCK

This is important:

> do NOT rerun the whole pipeline unnecessarily.

Retry only the affected dependency chain.

---

# Retry Weighting

Retry behavior should also respect weighting.

Examples:

### Critical field

* aggressive retry
* retry allowed
* retry downstream dependency chain
* block if unresolved

### Important field

* maybe one retry
* otherwise downgrade confidence

### Optional field

* no retry needed
