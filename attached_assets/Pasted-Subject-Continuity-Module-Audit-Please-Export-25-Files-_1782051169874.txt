AUDIT INSTRUCTIONS:

Do a thorough line-by-line review of each file (read every line, NOT a keyword scan). Focus on these continuity-specific risks:

1. SILENT FAILURE
   - Are there any empty catch blocks `catch {}` or `.catch(() => [])` that swallow errors without logging?
   - If a scheduled job, worker, or cycle fails, does anyone get notified, or does it die silently?
   - Are failures logged with a structured tag (e.g. console.error with a context label)?

2. ZOMBIE / STUCK STATE
   - If a worker crashes mid-run, does it leave records stuck in a "running" / "in-progress" state forever?
   - Is there try/catch/finally that guarantees a job is always finalized (success OR failure)?
   - Is there dead-cycle detection (a job that never completes)?

3. LOCKS & CONCURRENCY
   - Are run-locks released correctly even when an exception is thrown?
   - Can two workers grab the same job at once (race condition)?
   - Are locks held too long (blocking other runs)?

4. RETRY LOGIC
   - Are partial/failed cycles retried correctly?
   - Is there an infinite-retry risk (a job that keeps failing and retrying forever)?
   - Is there a max-retry ceiling?

5. GRACEFUL SHUTDOWN
   - Are all timers and intervals tracked and cleared on SIGTERM?
   - Does an in-flight job get a chance to finish or roll back on shutdown?

6. UNBOUNDED QUERIES
   - Any DB query without a `.limit()` that could load a huge table into memory?

7. ERROR DISCLOSURE (routes only)
   - Does early-warning/routes.ts return raw `err.message` to the client?
