# REQUIRED SYSTEM CHANGES

## 1. Shared Strategic Context (SSC)

All engines must read and write to a **single evolving context object**

This context must include:

* problem_map
* pain_map
* desire_map
* objection_map
* trust_map
* awareness_meaning
* narrative_constraints
* contradictions
* downstream_requirements

### Engine behavior:

Each engine must:

1. Read full context
2. Interpret signals within that context
3. Add structured insights (not overwrite)
4. Pass enriched context forward

No engine is allowed to reinterpret reality from scratch.

---

## 2. Problem Registry (CRITICAL)

We need a **central evolving list of problems**

Not just initial problems — ALL problems discovered during execution.

### Structure:

Each problem must include:

* id
* source_engine
* type (market / audience / structural / conversion)
* description
* severity
* confidence
* status (open / resolved / deferred)

### Engine responsibility:

Each engine must:

* Read existing problems
* Solve relevant ones
* Add new problems if discovered

### Control Layer responsibility:

* Detect unresolved critical problems
* Detect ignored problems
* Block or downgrade if necessary

---

## 3. Canonical Meaning Contract

We must standardize the meaning of all strategic labels.

Example:

“product_aware” must NOT be interpreted differently across engines.

Instead, it must be expanded into structured meaning like:

* trust level
* comparison behavior
* conversion readiness
* proof requirements
* education level

All engines must consume the same definition.

No engine is allowed to redefine core meanings.

---

## 4. Reason Trace (MANDATORY)

Every engine must output:

signal → interpretation → constraint → decision

This is required to:

* trace contradictions
* debug logic
* enable correction

### CRITICAL ADDITION:

Reason Trace must NOT be treated as debug output.

It must be part of the **structured data contract passed between engines**.

This means:

* Each engine must expose its reasoning in a machine-readable format
* Downstream engines MUST read and validate upstream reasoning before proceeding
* Any contradiction between reasoning layers must be detectable and actionable

Without this, engines will continue operating with isolated logic.

---

## 5. Confidence System Refactor

We must separate:

### A. Data Confidence

* reflects data quality only
* DOES NOT block execution
* only informs visibility

### B. Engine Confidence

* reflects correctness of engine logic
* determines whether correction is needed

### Rules:

* Low data confidence → continue execution
* Low engine confidence → trigger correction
* NEVER block due to weak data alone

---

## 6. Self-Correcting System Role

Self-correcting must:

* Fix engine logic
* NOT compensate for weak data
* NOT modify memory directly
* NOT override final system authority

Triggers:

* Low engine confidence
* Contradictions
* Logical inconsistencies

---

## 7. Control Layer (Final Authority)

The Control Layer must:

1. Consume all engine outputs
2. Evaluate:

   * structural completeness
   * problem resolution status
   * contradictions
   * engine confidence
3. Produce a final verdict:

   * PASS
   * DOWNGRADE
   * REPAIR
   * BLOCK

---

## 8. Repair Actions (NOT reactions)

The system must include **bounded repair actions**, not passive reactions.

Allowed actions:

* Re-run specific engines (max 1 time)
* Inject missing structural components (e.g. conversion path)
* Downgrade decisions (scale → test)

Not allowed:

* Re-run offer generation freely
* Override integrity score
* Modify memory directly
