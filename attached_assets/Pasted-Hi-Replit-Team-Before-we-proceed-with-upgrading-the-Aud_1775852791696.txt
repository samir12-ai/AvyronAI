## 2. Signal Aggregation Logic (Replacing Volume Dependence)

We want to move away from:
- Comment count thresholds (e.g. ≥ 50)

Toward:
- Pattern strength detection, based on:
  - recurrence of the same pain/desire
  - consistency across sources

Example:
- Same pain appearing across captions + comments + TikTok hooks → strong signal
- Single-source signal → weak

Questions:
- Does any current layer already compute cross-source agreement or signal recurrence beyond keyword matching?
- Where is the best place to implement this:
  - Inside matchPatternClusters()?
  - After map construction (post-processing layer)?
  - Or within the Semantic Bridge?

## 3. Source Weighting / Signal Quality

We want to introduce weighting such as:
- Longer comments > short comments
- Structured reviews > generic comments
- High-performing content (TikTok) > low-engagement content

Questions:
- Is there any existing weighting system in:
  - evidence scoring
  - MIv3 semanticSignals quality score

## 4. Removing Mixed Inference Behavior (Stability Requirement)

Current behavior mixes:
- real comments
- captions
- bridge (MIv3 GPT signals)
- inferred segments (fallback)

We want to avoid unstable blending and move toward:
- deterministic output when signal is strong
- controlled fallback only when signal is weak

Questions:
- Where exactly is the decision made to activate:
  - Semantic Bridge
  - GPT-based segment construction
- Can this be gated explicitly (e.g. disable bridge under certain conditions)?

We are considering a structure where each competitor has:
