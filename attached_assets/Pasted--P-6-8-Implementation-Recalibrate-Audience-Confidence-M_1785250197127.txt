# P-6.8 Implementation — Recalibrate Audience Confidence Model Using Caption & Comment Evidence

The previous investigations established the following:

* The Audience Engine correctly loads all 10 configured competitors.
* The campaign contains 147 competitor posts and 104 real comments.
* The Audience Engine extracts valid pain signals.
* The pipeline fails because the confidence model does not promote any pain into a root cause.
* This causes:

  * `root_causes = []`
  * SGL missing `root_cause` coverage
  * `BLOCKED_BY_INTEGRITY`
  * downstream engines never executing
  * `strategy_roots` never being written

The audits also confirmed that the current confidence model assumes a level of evidence diversity that does not reflect how Avyron is intentionally designed.

Avyron's primary audience evidence comes from:

* Competitor captions
* Audience comments

Other sources (reviews, TikTok, website, etc.) are enrichment sources, not mandatory evidence.

Implement the correction.

Do not bypass SGL.

Do not create synthetic evidence.

Do not reduce integrity standards.

Fix the confidence model so it matches Avyron's intended evidence architecture.

# Architectural Principle

For Audience pain discovery:

```text
Caption + Comment = Primary Evidence
```

Reviews, TikTok, Website, Market Signals and any additional channels are supporting evidence only.

A campaign with strong captions and comments must be capable of producing validated pains and root causes.

Optional channels should increase confidence.

Their absence must never invalidate legitimate evidence.

---

# Required Changes

## 1. Replace Fixed Source Expectations

Remove the assumption that every campaign is expected to have five evidence sources.

Instead implement an Audience-specific evidence model.

Primary sources:

* Caption
* Comment

Optional corroboration:

* Review
* TikTok
* Website
* Market Signals
* Future sources

Primary evidence should determine whether a pain is valid.

Optional evidence should strengthen confidence.

---

## 2. Recalibrate Source Weighting

Support the following behaviour:

Caption only

↓

Valid evidence

↓

Lower confidence

Comment only

↓

Valid evidence

↓

Lower confidence

Caption + Comment

↓

Strong primary evidence

↓

Highest primary confidence

Caption + Comment + Optional Sources

↓

Additional corroboration bonus

Do not require optional sources to reach the base confidence.

---

## 3. Review Frequency Normalization

Audit the current assumption requiring approximately 10% corpus frequency.

Design a frequency model that generalizes across campaigns of different sizes.

Frequency should reflect meaningful repetition.

It should not require a pain cluster to dominate the entire corpus.

---

## 4. Preserve Confidence Quality

Do not simply lower thresholds.

The confidence model should still distinguish between:

* weak evidence
* moderate evidence
* strong evidence

Root causes must continue to require genuinely strong evidence.

---

## 5. Preserve Traceability

Every promoted root cause must retain complete provenance.

Include:

* supporting captions
* supporting comments
* competitor IDs
* occurrence counts
* source types
* confidence breakdown
* final confidence
* provenance classification

No synthetic evidence.

No fake corroboration.

---

## 6. Version the Confidence Model

Do not overwrite historical behaviour.

Introduce a new confidence model version.

Example:

```text
audience-confidence-v2
```

Store the version alongside future audience snapshots.
