# 1. Problem (Confirmed)

Statistical Validation currently uses:

> **lexical word-overlap matching** to link claims → signals

Specifically:

* ≥1 overlapping word (≥4 chars) required
* otherwise claim = orphaned

Valid claims are being rejected:

* Offer: “Reduce financial anxiety…”
* Audience pains: “confusion”, “overwhelm”, “decision paralysis”

→ No shared words
→ orphaned
→ validationState = rejected

Despite:

* correct upstream signals
* correct positioning
* correct logic

# 3. Required Fix — Semantic Lineage Matching

Replace `findLineageMatch()` logic with **semantic grounding**, not lexical matching.

---

## Required Behavior

For each claim:

### Step A — Compute semantic similarity

* claim.text vs upstreamLineage[].signalText
* use embeddings / semantic similarity

### Step B — Assign parentSignalId

* select best matching signal(s)
* allow multi-match if needed

### Step C — Confidence-weighted mapping

* high similarity → strong grounding
* medium similarity → weak/inferred grounding
* low similarity → orphan (valid case)

---

## Important

* Matching must be **system-calculated**, not LLM-reported
* Must be deterministic
* Must not depend on wording coincidence

---
