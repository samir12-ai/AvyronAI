✅ PHASE 1 — Audience Engine Validation (Core)

Run multiple full executions of the Audience Engine on the existing campaign(s).

Verify:

1. Signal Quality System
	•	Comments are correctly classified:
	•	NOISE / LOW / MED / HIGH
	•	Emoji-only and low-signal comments are filtered correctly
	•	HIGH-quality comments contribute more weight than LOW ones

2. Weighted Matching Behavior
	•	Strong signals (repeated meaningful comments) dominate output
	•	Weak/generic signals do not dominate maps
	•	No inflation from repeated captions

3. Source Tracking
	•	Each signal correctly tracks:
	•	comments
	•	captions
	•	Source diversity affects confidence as expected

4. Bridge Suppression
	•	When primaryStrength ≥ threshold:
	•	Semantic Bridge is NOT used
	•	When data is weak:
	•	Bridge activates correctly (rescue mode only)

5. Diagnostics Output
	•	Logs must show:
	•	HIGH / MED / LOW / NOISE counts
	•	primaryStrength value
	•	Snapshot must include inputSummary

⸻

✅ PHASE 2 — Consistency Across Runs

Run the same campaign multiple times.

Verify:
	•	Results are stable (not random)
	•	Same input → similar output maps
	•	No fluctuation caused by:
	•	ordering
	•	timing
	•	partial data

⸻

✅ PHASE 3 — Edge Case Testing

Test the engine behavior under different real conditions:

Case A — Low Comment Volume
	•	Ensure:
	•	system still produces output
	•	no crashes
	•	bridge activates only if needed

Case B — High Noise Dataset
	•	Many emoji / short comments
	•	Ensure:
	•	filtering works
	•	signal quality still holds

Case C — Caption-Dominant Data
	•	Few comments, strong captions
	•	Ensure:
	•	captions still produce valid signals
	•	no over-reliance on bridge

⸻

	•	No runtime errors in logs

	•	No undefined/null crashes
