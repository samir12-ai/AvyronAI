# 3. Fix the Run-Scoped Truth Problem First

## Mandatory architecture rule:
Every engine in a pipeline run must consume the same run-scoped upstream snapshot chain.

No engine is allowed to independently select:
- latest snapshot
- latest complete snapshot
- latest by account
- latest by timestamp

That behavior is now forbidden.

## Required implementation:
The orchestrator must construct a single run-scoped snapshot map, and every engine must consume from that map only.

Example conceptually:

- orchestrator creates current run context
- for each engine result, the exact produced snapshot ID is registered in the run context
- every downstream engine receives upstream snapshot IDs directly from that context
- Integrity, Offer, Funnel, Awareness, Persuasion, Channel Selection, and all downstream consumers must use only those IDs

## Hard requirement:
No downstream engine may resolve upstream state from the database on its own if that state already exists inside the active run context.

## Goal:
One pipeline run = one truth set.
