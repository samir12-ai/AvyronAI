Core Issue

The Offer Engine is being executed in two different modes depending on the caller, due to inconsistent handling of strategyRoot.

1. Orchestrator Path
	•	Calls runOfferEngine(...) with:

strategyRoot = undefined


	•	This forces the engine into:
	•	free_generation mode
	•	strict lexical validators (blocking)
	•	Result:
	•	POSITIONING_MISMATCH
	•	low confidence
	•	unstable outputs

⸻

2. Manual Route Path (/api/offer/analyze)
	•	Calls runOfferEngine(...) with:

strategyRoot = activeRoot


	•	This enables:
	•	deterministic skeleton-based generation
	•	validators downgrade to advisory
	•	Result:
	•	strong, stable output

⸻

Resulting System Behavior

This mismatch explains everything we observed:
	•	Strong upstream layers (Positioning / Mechanism)
	•	Awareness constraints correctly detected
	•	Offer:
	•	fails in orchestrator
	•	succeeds in manual route
	•	“Invalid root” warnings while still producing full offers

⸻

Required Fixes

1. Orchestrator MUST pass strategyRoot

File:
server/orchestrator/index.ts

Action:
	•	Load the active strategy root
	•	Pass it into:

runOfferEngine(..., strategyRoot)



This is mandatory.

No fallback, no optional behavior.

⸻

2. Persist strategyRootId in offerSnapshots

File:
server/orchestrator/index.ts

strategyRootId: strategyRoot.id



This ensures:
	•	correct invalidation
	•	proper linkage

File:
server/offer-engine/routes.ts
