# 🚀 Phase 1 — Promote TikTok & Reviews into First-Class Signal Sources

This phase should extend the existing system — not replace it.

## 1. TikTok Success Qualification Layer (Competitor Posts)

Build a per-post scoring layer BEFORE signals enter MI analysis.

Requirements:

* For each TikTok post:

  * Compute **relative performance vs creator baseline**
  * Use:

    * views vs average
    * engagement ratios
    * shares/comments if available

* Output classification:

  * HIGH_PERFORMING
  * MID_PERFORMING
  * LOW_PERFORMING

* Store:

  * classification
  * relativeScore (0–1)

* Integration:

  * Only HIGH + MID posts should meaningfully influence MI signals
  * LOW posts should not act as validation signals

Important:
This must be implemented for **competitor posts**, not just user performance (which already exists).

---

## 2. Google Reviews → Pain & Objection Layer

Extend existing signal extraction logic (similar to comments):

* Build:

  * pain signal extraction
  * objection extraction
  * clustering (similar to NarrativeObjectionExtractor)

* Output:

  * pain clusters
  * objection clusters
  * frequency / dominance indicators

* Reviews must remain:

  * raw in `ci_competitor_reviews`
  * processed outputs stored in MI snapshots (like existing objectionMapData)

---

## 3. Promote TikTok & Reviews into Source Types

Extend existing `signal-normalizer.ts`:

* Add:

  * TikTok as SourceType
  * Google Reviews as SourceType

* Integrate into:

  * SIGNAL_WEIGHTS matrix
  * MultiSourceSignals interface

Important:
Do NOT replace existing weighting — extend it.

---

## 4. Automatic Scraping + Analysis Flow for TikTok and Google Reviews

Right now, Instagram has an automated lifecycle and TikTok / Reviews are more manual. We want TikTok and Google Reviews to behave like Instagram operationally.

Required behavior:

* TikTok scraping should run automatically, not only via manual trigger
* Google Reviews scraping should run automatically, not only via manual trigger
* After scraping:

  * data should be normalized / processed
  * then included in MI analysis
  * then flow into the new decision layer

In other words, TikTok and Reviews should become part of the same automatic market-intelligence loop as Instagram.

Please implement this in a way that fits the existing worker / queue architecture rather than adding a completely separate execution path.

---

## 5. Fallback Logic — New System Must Still Work When Sources Are Missing

The new system must not depend on all sources being present at all times.

Required fallback behavior:

* If TikTok and Google Reviews are both present:

  * run the full new system using Instagram + TikTok + Reviews + existing sources

* If TikTok exists but Google Reviews does not:

  * system should still run correctly on the new logic

* If Google Reviews exists but TikTok does not:

  * system should still run correctly on the new logic

* If neither TikTok nor Google Reviews exists:

  * system should still run on Instagram + existing sources **using the new decision layer**, not by silently falling back to the old pre-decision behavior

This is very important:
Even when TikTok / Reviews are missing, the system should still execute the **new architecture**, only with fewer sources and reduced confidence where appropriate.

We do not want:

* new behavior when sources exist
* old behavior when they do not

We want:

* one consistent system
* graceful degradation based on available sources
