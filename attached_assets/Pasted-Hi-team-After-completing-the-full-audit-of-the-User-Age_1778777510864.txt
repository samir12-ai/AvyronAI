Hi team,

After completing the full audit of the User Agent Pipeline weekly evaluation flow, we identified that the issue was not an agent execution failure, but a systemic operational continuity failure.

The system currently contains strong evaluation doctrine, semantic enforcement, and fail-safe guards, but lacks a true operational continuity layer that guarantees lifecycle persistence, cadence maintenance, and autonomous execution continuity.

This is now a top-priority architecture issue.

The system must evolve from:
“capable of evaluating”
to:
“guaranteed to continuously operate, monitor, recover, and self-surface operational degradation.”

The recent incident exposed multiple categories of operational gaps which must now be permanently sealed.

==================================================
MANDATORY IMPLEMENTATIONS
=========================

1. Autonomous Scheduler / Continuity Heartbeat Layer

---

A real autonomous execution layer must be added.

Current issue:

* No scheduler invokes runBoss()
* Weekly cadence depends on manual triggering
* Windows never open unless explicitly called
* Entire evaluation lifecycle can silently stall

Required:

* Add scheduled orchestration heartbeat
* Daily/hourly cadence with idempotent campaign locking
* Automatic boss execution for all eligible campaigns
* Lifecycle continuity monitor
* Dead-cycle detection
* Missed-window detection
* Missing-run escalation

The system must NEVER depend on manual invocation for core evaluation cycles again.
